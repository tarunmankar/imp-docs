## 📖 Introduction: The AI-First Philosophy

Yeh guide un logon ke liye hai jo:
- Non-technical founder hain aur software agency banana chahte hain
- Beginner freelancer hain jo premium clients lena chahte hain
- Existing developers hain jo apni speed 10x karna chahte hain

**Core Mindset:** *Tum Manager ho. AI tumhara Developer hai.*

Tumhara kaam hai — sochna, plan karna, test karna, aur client se baat karna. AI ka kaam hai — code likhna.

---

### ⚖️ The 5 Golden Rules

| # | Rule | Why It Matters |
|---|------|----------------|
| 1 | **Database First, Logic Second, UI Last** | UI bina foundation ke toot jaata hai |
| 2 | **Chunking** | AI ko ek kaam ek baar do — confuse mat karo |
| 3 | **No API Keys in Code** | Security breach se bachao — `.env.local` use karo |
| 4 | **Refresh Chats** | 30-40 messages ke baad nayi chat — context fresh rakho |
| 5 | **Test Before Saving** | Browser mein verify karo, tabhi Git commit karo |

> ⚠️ **Critical Warning:** Ye 5 rules tod doge to project guaranteed fail hoga. Ek bhi exception mat karna.

## 🔐 Part 5: Security, Deployment & Optimization

---

### 5.1 Supabase Row Level Security (RLS)

> ⚠️ **Without RLS: User A can see ALL users' data. This is a critical security hole.**

**Always enable RLS first:**
```sql
-- Enable RLS on all tables
ALTER TABLE products ENABLE ROW LEVEL SECURITY;
ALTER TABLE sales ENABLE ROW LEVEL SECURITY;
ALTER TABLE customers ENABLE ROW LEVEL SECURITY;
```

**Standard Policy Patterns:**

```sql
-- SELECT: Only see your own data
CREATE POLICY "Users can view own data"
ON products FOR SELECT
USING (auth.uid() = user_id);

-- INSERT: Only insert as yourself
CREATE POLICY "Users can insert own data"
ON products FOR INSERT
WITH CHECK (auth.uid() = user_id);

-- UPDATE: Only update your own data
CREATE POLICY "Users can update own data"
ON products FOR UPDATE
USING (auth.uid() = user_id);

-- DELETE: Only delete your own data
CREATE POLICY "Users can delete own data"
ON products FOR DELETE
USING (auth.uid() = user_id);
```

**Multi-tenant (Multiple clients, one DB):**
```sql
-- Organization-based access
CREATE POLICY "Org members can view"
ON products FOR SELECT
USING (
  org_id IN (
    SELECT org_id FROM org_members
    WHERE user_id = auth.uid()
  )
);
```

### 7.2 Scope Creep Se Kaise Bachein

> **Scope Creep:** Client ne pehle kuch aur maanga tha, ab kuch aur maang raha hai — bina extra payment ke.

**Script for handling scope creep:**
```
"[Client Name], yeh feature bahut achha idea hai!

Lekin yeh hamare original agreement ke bahar hai.
Main isko ek separate quote mein add kar sakta hoon.

Original scope ke andar hum Day 15 pe deliver karenge.
Yeh naya feature: approximately [X] din extra + ₹[Amount] extra.

Aap batao — kya is feature ko Phase 2 mein add karein?"
```

### 7.3 Contract Template (Key Clauses)

Hamesha ek simple written agreement rakho jisme yeh ho:

```
1. SCOPE OF WORK
   - [List exact modules and features]
   - "Any feature not listed above is out of scope"

2. PAYMENT TERMS
   - 30% advance before start
   - 40% on MVP approval (Day 10)
   - 30% on final delivery

3. TIMELINE
   - Delivery: [Specific date]
   - Delays due to client feedback: client's responsibility

4. HOSTING & MAINTENANCE
   - Hosting charges: [Who pays, how much annually]
   - Post-delivery support: [X] months free
   - After that: AMC at ₹[Amount]/month

5. INTELLECTUAL PROPERTY
   - Code ownership transfers to client on full payment
   - You retain right to use similar code for other clients
   - Client cannot resell the software

6. LIMITATION OF LIABILITY
   - Max liability = amount paid for the project
```

### Common Debugging Checks
```
❌ "Cannot read properties of undefined"
→ Data load hone se pehle render ho raha hai
→ Fix: Optional chaining use karo (data?.property)

❌ "RLS violation" / "new row violates RLS"
→ user_id correctly insert nahi ho raha
→ Fix: auth.uid() check karo INSERT policy mein

❌ "Module not found"
→ Import path galat hai
→ Fix: File path check karo, case sensitivity dekho

❌ "Hydration mismatch"
→ Server aur client render alag hai
→ Fix: 'use client' directive check karo
```
